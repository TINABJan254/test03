## Java 12

JDK 12 được phát hành vào ngày 19 tháng 3 năm 2019, đây là một phiên bản không phải LTS.

Bài viết này sẽ chọn lọc một số tính năng mới tương đối quan trọng để giới thiệu chi tiết:

- [JEP 189: Shenandoah: A Low-Pause-Time Garbage Collector (Experimental)](https://openjdk.org/jeps/189)
- [JEP 325: Switch Expressions (Preview) (switch 表达式, 特性预览)](https://openjdk.org/jeps/325)
- [JEP 334: JVM Constants API (JVM 常量 API)](https://openjdk.org/jeps/334)
- [JEP 344: Abortable Mixed Collections for G1 (G1 可中止的混合收集集合)](https://openjdk.org/jeps/344)
- [JEP 346: Promptly Return Unused Committed Memory (G1 及时返回未使用的已分配内存)](https://openjdk.org/jeps/346)

Hình dưới đây thống kê số lượng tính năng mới và thời gian cập nhật mang lại bởi từng phiên bản từ JDK 8 đến JDK 25:

![Số lượng tính năng mới và thời gian cập nhật mang lại bởi từng phiên bản từ JDK 8 đến JDK 25](https://oss.javaguide.cn/github/javaguide/java/new-features/jdk8~jdk24.png)

### JEP 189: Shenandoah (Bộ thu gom rác thời gian tạm dừng thấp, Thử nghiệm)

Shenandoah là bộ thu gom rác tạm dừng thấp do Red Hat chủ đạo phát triển, mục tiêu là khi heap lớn vẫn cố gắng duy trì thời gian tạm dừng ngắn và độc lập tương đối với kích thước heap.

So với ZGC mã nguồn mở trong Java 11 (cần nâng cấp lên JDK 11 mới có thể sử dụng), Shenandoah GC có phiên bản JDK8u ổn định, ở thời điểm Java 8 chiếm thị phần chủ yếu hiện nay nó có tính khả thi trong việc triển khai cao hơn.

### JEP 344 & JEP 346: Tối ưu hóa Bộ thu gom G1

Java 12 mang lại hai cập nhật cho Bộ thu gom rác mặc định G1:

- **Tập hợp thu gom hỗn hợp có thể hủy bỏ**: Triển khai của JEP 344, để đạt được mục tiêu thời gian tạm dừng do người dùng cung cấp, JEP 344 chia tập hợp khu vực cần thu hồi (tập hợp thu gom hỗn hợp) thành phần bắt buộc và phần tùy chọn, giúp Bộ thu gom rác G1 có thể hủy bỏ quá trình thu gom rác. G1 có thể hủy bỏ việc thu hồi phần tùy chọn để đạt được mục tiêu thời gian tạm dừng
- **Trả lại kịp thời bộ nhớ đã phân bổ chưa sử dụng**: Triển khai của JEP 346, tăng cường G1 GC, để khi rảnh rỗi tự động trả bộ nhớ heap Java cho hệ điều hành

### JEP 334: JVM Constants API (JVM Hằng số API)

Đã giới thiệu một API để mô hình hóa các mô tả danh nghĩa của các file class cốt lõi và artifact runtime, đặc biệt là các hằng số có thể tải từ hằng số pool (constant pool).

API này cung cấp một tập hợp các interface và lớp tiện ích, dùng để biểu thị và thao tác các entry trong constant pool của file class. Nó chủ yếu bao gồm:

- **Interface mô tả hằng số**: Interface `ConstantDesc` và các interface con của nó, dùng để mô tả các loại hằng số
- **Kiểu giá trị hằng số**: `ClassDesc`, `MethodTypeDesc`, `MethodHandleDesc`, `DynamicConstantDesc`,...
- **Phương thức dẫn dắt (Bootstrap methods)**: Hỗ trợ lệnh `invokedynamic` và phương thức dẫn dắt động hằng số

API này chủ yếu để hỗ trợ các kịch bản sau:

1. **Thao tác file class**: Cung cấp một phương thức chuẩn hóa để mô tả và thao tác constant pool trong file class
2. **Sinh bytecode**: Đơn giản hóa việc tương tác giữa framework sinh bytecode (như ASM) và mã Java
3. **Tăng cường Reflection**: Làm cho các thao tác reflection an toàn hơn về kiểu và có tính diễn đạt mạnh hơn
4. **Công cụ biên dịch**: Cung cấp trừu tượng tốt hơn cho trình biên dịch và các công cụ sinh mã

API này là cải tiến tầng dưới quan trọng trong Java 12, đặt nền móng cho các thao tác bytecode và tính năng trình biên dịch sau này.

### JEP 325: Switch Expressions (Switch biểu thức, Xem trước)

Cú pháp `switch` truyền thống tồn tại vấn đề dễ quên viết `break`, hơn nữa từ góc độ sạch sẽ của mã nguồn, nhiều break về bản chất cũng là một sự lặp lại.

Java 12 tăng cường `switch` biểu thức, sử dụng khối thực thi sau khi khớp điều kiện tương tự cú pháp lambda, không cần viết thêm break.

```java
switch (day) {
    case MONDAY, FRIDAY, SUNDAY -> System.out.println(6);
    case TUESDAY                -> System.out.println(7);
    case THURSDAY, SATURDAY     -> System.out.println(8);
    case WEDNESDAY              -> System.out.println(9);
}
```

JDK 13 được phát hành vào ngày 17 tháng 9 năm 2019, đây là một phiên bản không phải LTS.

Bài viết này sẽ chọn lọc một số tính năng mới tương đối quan trọng để giới thiệu chi tiết:

- [JEP 351: ZGC: Uncommit Unused Memory (ZGC giải phóng bộ nhớ chưa sử dụng)](https://openjdk.org/jeps/351)
- [JEP 355: Text Blocks (Preview) (Khối văn bản, Tính năng xem trước)](https://openjdk.org/jeps/355)
- [JEP 354: Switch Expressions (Second Preview) (Switch biểu thức, Xem trước lần 2)](https://openjdk.org/jeps/354)

Hình dưới đây thống kê số lượng tính năng mới và thời gian cập nhật mang lại bởi từng phiên bản từ JDK 8 đến JDK 24:

![](https://oss.javaguide.cn/github/javaguide/java/new-features/jdk8~jdk24.png)

### JEP 351: ZGC (Giải phóng bộ nhớ chưa sử dụng)

ZGC được giới thiệu thử nghiệm trong Java 11 gặp phải vấn đề chưa chủ động giải phóng bộ nhớ chưa sử dụng cho hệ điều hành trong quá trình sử dụng thực tế.

ZGC heap được cấu thành bởi một nhóm các vùng heap gọi là ZPages. Khi làm rỗng các vùng ZPages trong chu kỳ GC, chúng sẽ được giải phóng và trả về bộ đệm trang **ZPageCache**, các ZPages trong bộ đệm này được tổ chức theo thứ tự ít sử dụng nhất gần đây (LRU) và theo kích thước.

Trong Java 13, ZGC sẽ trả lại cho hệ điều hành các trang được đánh dấu là lâu không sử dụng, nhờ đó chúng có thể được các tiến trình khác tái sử dụng.

### JEP 350: Dynamic CDS Archives (Lưu trữ CDS động)

Trong Java 13 đã tiếp tục đơn giản hóa, cải tiến và mở rộng việc chia sẻ dữ liệu class ứng dụng (AppCDS) được giới thiệu trong Java 10, cụ thể: **cho phép lưu trữ class động khi kết thúc thực thi ứng dụng Java**, các class cụ thể có thể được lưu trữ bao gồm tất cả các class ứng dụng và class trong thư viện tham chiếu đã được tải nhưng không thuộc CDS cơ sở mặc định.

Điều này nâng cao tính khả dụng của việc chia sẻ dữ liệu class ứng dụng ([AppCDS](https://openjdk.java.net/jeps/310)). Không cần người dùng phải chạy thử nghiệm để tạo danh sách class cho mỗi ứng dụng.

```bash
java -XX:ArchiveClassesAtExit=my_app_cds.jsa -cp my_app.jar
java -XX:SharedArchiveFile=my_app_cds.jsa -cp my_app.jar
```

### JEP 355: Text Blocks (Khối văn bản, Xem trước)

Giải quyết vấn đề khi Java định nghĩa chuỗi nhiều dòng chỉ có thể biến thông hỗ trợ thông qua ký tự thoát xuống dòng hoặc ký tự nối xuống dòng, giới thiệu **dấu ngoặc kép ba** để định nghĩa văn bản nhiều dòng.

Java 13 hỗ trợ bất kỳ nội dung nào ở giữa hai ký hiệu `"""` đều sẽ được giải thích là một phần của chuỗi, bao gồm cả ký tự xuống dòng. Lưu ý: "hai" ở đây nên hiểu là "một cặp", tức là bắt đầu và kết thúc mỗi bên một cái.

Cách viết HTML trước khi hỗ trợ Text Blocks:

```java
String json ="{\n" +
              "   \"name\":\"mkyong\",\n" +
              "   \"age\":38\n" +
              "}\n";
```

Cách viết HTML sau khi hỗ trợ Text Blocks:

```java
 String json = """
                {
                    "name":"mkyong",
                    "age":38
                }
                """;
```

Cách viết SQL trước khi hỗ trợ Text Blocks:

```sql
String query = "SELECT `EMP_ID`, `LAST_NAME` FROM `EMPLOYEE_TB`\n" +
               "WHERE `CITY` = 'INDIANAPOLIS'\n" +
               "ORDER BY `EMP_ID`, `LAST_NAME`;\n";
```

Cách viết SQL sau khi hỗ trợ Text Blocks:

```sql
String query = """
               SELECT `EMP_ID`, `LAST_NAME` FROM `EMPLOYEE_TB`
               WHERE `CITY` = 'INDIANAPOLIS'
               ORDER BY `EMP_ID`, `LAST_NAME`;
               """;
```

Giới thiệu các phương thức liên quan đến Text Blocks (`formatted()`, `stripIndent()`, `translateEscapes()`) vui lòng xem phần [Tăng cường API - Tăng cường String (Các phương thức liên quan đến Text Blocks)](#tang-cuong-string-cac-phuong-thuc-lien-quan-den-text-blocks) của bài viết này.

### JEP 354: Switch Expressions (Switch biểu thức, Xem trước lần 2)

Trong `Switch` biểu thức bổ sung thêm một từ khóa dùng để thoát khỏi khối `Switch` là `yield`, chủ yếu dùng để trả về một giá trị.

Sự khác biệt giữa `yield` và `return` nằm ở chỗ: `return` kết thúc phương thức hiện tại và trả về kết quả, còn `yield` kết thúc nhánh biểu thức `switch` hiện tại và tạo ra giá trị của biểu thức đó. Biểu thức `switch` bắt buộc phải bao phủ tất cả các đầu vào có thể, nhưng không nhất thiết cần nhánh `default` khi đã liệt kê hết tất cả các giá trị.

```java
 private static String descLanguage(String name) {
        return switch (name) {
            case "Java": yield "object-oriented, platform independent and secured";
            case "Ruby": yield "a programmer's best friend";
            default: yield name +" is a good language";
        };
 }
```

## Tăng cường API

Không phải tất cả các thay đổi API đều được phát hành thông qua JEP (Java Enhancement Proposal).

Trong quy trình phát triển JDK: **JEP** thường được dùng cho các thay đổi lớn, ví dụ giới thiệu tính năng ngôn ngữ mới (như biểu thức `switch`), cơ chế JVM mới (như ZGC) hoặc tái cấu trúc thư viện quy mô lớn. Còn các thao tác như bổ sung một vài phương thức trong lớp hiện có như `String.indent()`, thường được coi là bảo trì thư viện thông thường. Chúng được các nhà phát triển JDK trực tiếp nộp và xem xét thông qua các thẻ ticket của **JBS (JDK Bug System)**, sau đó phát hành trực tiếp cùng với phiên bản.

### Tăng cường String

Java 12 bổ sung hai phương thức xử lý chuỗi.

#### indent() - Phương thức thụt lề

Phương thức `indent()` có thể thực hiện thụt lề chuỗi.

```java
String text = "Java";
// Thụt lề 4 ô
text = text.indent(4);
System.out.println(text);
text = text.indent(-10);
System.out.println(text);
```

Kết quả:

```plain
     Java
Java
```

#### transform() - Phương thức chuyển đổi

Phương thức `transform()` có thể dùng để biến đổi chuỗi được chỉ định.

```java
String result = "foo".transform(input -> input + " bar");
System.out.println(result); // foo bar
```

### Tăng cường Files

Java 12 đã thêm phương thức `mismatch()` để so sánh hai file:

```java
public static long mismatch(Path path, Path path2) throws IOException
```

Phương thức `mismatch()` dùng để so sánh hai file, và trả về vị trí byte không khớp đầu tiên, nếu hai file giống nhau sẽ trả về `-1L`.

Ví dụ mã nguồn (Trường hợp nội dung hai file giống nhau):

```java
Path filePath1 = Files.createTempFile("file1", ".txt");
Path filePath2 = Files.createTempFile("file2", ".txt");
Files.writeString(filePath1, "Java 12 Article");
Files.writeString(filePath2, "Java 12 Article");

long mismatch = Files.mismatch(filePath1, filePath2);
assertEquals(-1, mismatch);
```

Ví dụ mã nguồn (Trường hợp nội dung hai file không giống nhau):

```java
Path filePath3 = Files.createTempFile("file3", ".txt");
Path filePath4 = Files.createTempFile("file4", ".txt");
Files.writeString(filePath3, "Java 12 Article");
Files.writeString(filePath4, "Java 12 Tutorial");

long mismatch = Files.mismatch(filePath3, filePath4);
assertEquals(8, mismatch);
```

### Tăng cường NumberFormat

Trong Java 12, `NumberFormat` đã bổ sung hỗ trợ định dạng cho các con số phức tạp:

```java
NumberFormat fmt = NumberFormat.getCompactNumberInstance(Locale.US, NumberFormat.Style.SHORT);
String result = fmt.format(1000);
System.out.println(result);
```

Kết quả:

```plain
1K
```

### Tăng cường Socket API

Java 13 đã viết lại tầng dưới của Socket API, `NioSocketImpl` là sự thay thế trực tiếp cho `PlainSocketImpl`, nó sử dụng lock trong package `java.util.concurrent` thay vì phương thức synchronized. Nếu muốn dùng triển khai cũ, vui lòng sử dụng `-Djdk.net.usePlainSocketImpl=true`.

Hơn nữa, trong Java 13 mặc định sử dụng triển khai Socket mới.

```java
public final class NioSocketImpl extends SocketImpl implements PlatformSocketImpl {
}
```

### Tăng cường FileSystems

Trong Java 13, lớp `FileSystems` bổ sung 3 phương thức mới dưới đây, để dễ dàng hơn trong việc sử dụng nhà cung cấp file system coi nội dung file là file system:

- `newFileSystem(Path)`
- `newFileSystem(Path, Map<String, ?>)`
- `newFileSystem(Path, Map<String, ?>, ClassLoader)`

### Tăng cường String (Các phương thức liên quan đến Text Blocks)

Java 13 giới thiệu tính năng xem trước Text Blocks, lớp `String` bổ sung thêm 3 phương thức mới để thao tác với Text Blocks:

- `formatted(Object... args)`: Tương tự phương thức `format()` của `String`. Bổ sung nó để hỗ trợ thiết lập định dạng của Text Blocks.
- `stripIndent()`: Dùng để loại bỏ khoảng trắng ở đầu và cuối mỗi dòng trong Text Blocks.
- `translateEscapes()`: Chuỗi thoát ký tự như _"\\\t"_ được chuyển đổi thành _"\t"_

Do Text Blocks là một chức năng xem trước, có thể bị xóa trong các phiên bản tương lai, do đó các phương thức mới này được đánh dấu là deprecated.

```java
@Deprecated(forRemoval=true, since="13")
public String stripIndent() {
}
@Deprecated(forRemoval=true, since="13")
public String formatted(Object... args) {

}
@Deprecated(forRemoval=true, since="13")
public String translateEscapes() {
}
```

Về giới thiệu chi tiết của Text Blocks, vui lòng xem phần [JEP 355: Text Blocks (Preview)](#jep-355-text-blocks-preview) của bài viết này.

## Bổ sung

### Về tính năng xem trước (Preview Features)

Trước tiên dán một đoạn văn bản gốc từ trang chủ Oracle: `This is a preview feature, which is a feature whose design, specification, and implementation are complete, but is not permanent, which means that the feature may exist in a different form or not at all in future JDK releases. To compile and run code that contains preview features, you must specify additional command-line options.`

Đây là một chức năng xem trước, thiết kế, quy chuẩn và triển khai của chức năng này là hoàn chỉnh, nhưng không phải là vĩnh viễn, điều này có nghĩa là chức năng đó có thể tồn tại ở hình thức khác hoặc hoàn toàn không tồn tại trong các phiên bản JDK tương lai. Để biên dịch và chạy mã nguồn chứa chức năng xem trước, bạn bắt buộc phải chỉ định thêm các tùy chọn dòng lệnh.

Lấy biểu thức `switch` làm ví dụ, nó bắt đầu xem trước từ Java 12, tiếp tục điều chỉnh trong Java 13, và chuyển thành tính năng ngôn ngữ chính thức trong Java 14. Sau khi chuyển chính thức, cú pháp và ngữ nghĩa của nó thuộc một phần quy chuẩn Java SE, không cần phải bật chức năng xem trước nữa.

Một mặt có thể thấy thái độ nghiêm túc của JDK với vai trò là nền tảng tiêu chuẩn khi bổ sung các tính năng mới, mặt khác cá nhân tôi cho rằng đối với các tính năng xem trước nên áp dụng thái độ cẩn trọng khi sử dụng. Việc thiết kế và triển khai tính năng là dễ dàng, nhưng giá trị thực tế của nó vẫn cần phải được kiểm chứng trong quá trình sử dụng.

### Tối ưu hóa JVM Virtual Machine

Mỗi lần phát hành phiên bản Java đều đi kèm với sự tối ưu hóa đối với JVM Virtual Machine, bao gồm việc cải tiến các thuật toán thu gom rác hiện có, giới thiệu các thuật toán thu gom rác mới, loại bỏ các thuật toán thu gom rác cũ kỹ không còn phù hợp với ngày nay.

Hướng tối ưu hóa tổng thể là **thể hiện thu gom rác hiệu quả, độ trễ thấp**.

Đối với các nhà phát triển ứng dụng hàng ngày có thể chú ý nhiều hơn đến các tính năng cú pháp mới, nhưng từ góc độ của một công ty, khi cân nhắc có nên nâng cấp nền tảng Java hay không thì sẽ cân nhắc nhiều hơn về **sự nâng cao của JVM runtime**.
