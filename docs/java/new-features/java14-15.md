## Java 14

JDK 14 được phát hành vào ngày 17 tháng 3 năm 2020, đây là một phiên bản không phải LTS.

Bài viết này sẽ chọn lọc một số tính năng mới tương đối quan trọng để giới thiệu chi tiết:

- [JEP 305: Pattern Matching for instanceof (Khớp mẫu cho instanceof, Xem trước)](https://openjdk.org/jeps/305)
- [JEP 358: Helpful NullPointerExceptions (Gợi ý chi tiết và chính xác cho NullPointerException)](https://openjdk.org/jeps/358)
- [JEP 361: Switch Expressions (Standard) (Switch biểu thức, Chính thức)](https://openjdk.org/jeps/361)
- [JEP 359: Records (Preview) (Từ khóa record, Tính năng xem trước)](https://openjdk.org/jeps/359)
- [JEP 368: Text Blocks (Second Preview) (Khối văn bản, Xem trước lần 2)](https://openjdk.org/jeps/368)
- [JEP 363: Remove the CMS Garbage Collector (Loại bỏ Bộ thu gom rác CMS)](https://openjdk.org/jeps/363)

Hình dưới đây thống kê số lượng tính năng mới và thời gian cập nhật mang lại bởi từng phiên bản từ JDK 8 đến JDK 25:

### JEP 305: Pattern Matching for instanceof (Khớp mẫu cho instanceof, Xem trước)

Java 14 tiếp tục đưa khớp mẫu instanceof làm tính năng xem trước, đây là chức năng được giới thiệu trong Java 14 (JEP 305).

Tính năng này cho phép ép kiểu đồng thời trong khi kiểm tra instanceof, tránh được việc ép kiểu cưỡng chế thủ công. Lưu ý: Khớp mẫu instanceof trong Java 14 là lần xem trước thứ nhất (JEP 305), trong Java 15 là lần xem trước thứ hai (JEP 375), và chính thức trở thành tính năng chuẩn trong Java 16 (JEP 394).

### JEP 358: Helpful NullPointerExceptions (Gợi ý chi tiết và chính xác cho NullPointerException)

Thông qua việc thêm tham số JVM `-XX:+ShowCodeDetailsInExceptionMessages`, có thể lấy được thông tin gọi hàm chi tiết hơn trong NullPointerException, giúp định vị và giải quyết vấn đề nhanh hơn.

```java
a.b.c.i = 99; // Giả sử đoạn mã này xảy ra NullPointer
```

Trước Java 14:

```java
Exception in thread "main" java.lang.NullPointerException
    at NullPointerExample.main(NullPointerExample.java:5)
```

Sau Java 14:

```java
 // 增加参数后提示的异常中很明确的告知了哪里为空导致
Exception in thread "main" java.lang.NullPointerException:
        Cannot read field 'c' because 'a.b' is null.
    at Prog.main(Prog.java:5)
```

### JEP 361: Switch Expressions (Switch biểu thức, Phiên bản chuẩn)

Switch (tính năng xem trước) được giới thiệu trong Java 12 đã trở thành phiên bản chính thức trong Java 14, không cần thêm tham số để bật, có thể sử dụng trực tiếp trong JDK 14.

Java 12 đã giới thiệu khối thực thi tương tự cú pháp lambda sau khi khớp điều kiện thành công cho biểu thức switch, không cần viết thêm break, Java 13 cung cấp `yield` để trả về giá trị trong khối block.

```java
String result = switch (day) {
            case "M", "W", "F" -> "MWF";
            case "T", "TH", "S" -> "TTS";
            default -> {
                if(day.isEmpty())
                    yield "Please insert a valid day.";
                else
                    yield "Looks like a Sunday.";
            }

        };
System.out.println(result);
```

### JEP 359: Records (Lớp record, Xem trước)

Từ khóa `record` có thể đơn giản hóa cách định nghĩa **lớp dữ liệu** (một lớp Java một khi đã khởi tạo thì không thể sửa đổi nữa), sử dụng `record` thay cho `class` để định nghĩa lớp, chỉ cần khai báo thuộc tính là có thể sở hữu các phương thức truy cập thuộc tính, cũng như các phương thức `toString()`, `hashCode()`, `equals()`.

Tương tự như việc sử dụng `class` để định nghĩa lớp, đồng thời sử dụng plugin lombok và gắn các annotation `@Getter,@ToString,@EqualsAndHashCode`.

```java
/**
 * 这个类具有两个特征
 * 1. 所有成员属性都是final
 * 2. 全部方法由构造方法，和两个成员属性访问器组成（共三个）
 * 那么这种类就很适合使用record来声明
 */
final class Rectangle implements Shape {
    final double length;
    final double width;

    public Rectangle(double length, double width) {
        this.length = length;
        this.width = width;
    }

    double length() { return length; }
    double width() { return width; }
}
/**
 * 1. 使用 record 声明的类会自动拥有上面类中的三个方法
 * 2. 在这基础上还附赠了 equals()，hashCode() 方法以及 toString() 方法
 * 3. toString 方法中包括所有成员属性的字符串表示形式及其名称
 */
record Rectangle(float length, float width) { }
```

### JEP 368: Text Blocks (Khối văn bản, Xem trước lần 2)

Trong Java 14, Text Blocks vẫn là tính năng xem trước, tuy nhiên, nó đã bổ sung thêm hai ký tự thoát mới:

- `\` : Biểu thị cuối dòng, không đưa vào ký tự xuống dòng
- `\s` : Biểu thị một khoảng trắng đơn lẻ

```java
String str = "凡心所向，素履所往，生如逆旅，一苇以航。";

String str2 = """
        凡心所向，素履所往， \
        生如逆旅，一苇以航。""";
System.out.println(str2);// 凡心所向，素履所往， 生如逆旅，一苇以航。
String text = """
        java
        c++\sphp
        """;
System.out.println(text);
//输出：
java
c++ php
```

- Bổ sung công cụ jpackage, ngoài việc đóng gói ứng dụng thành file jar tiêu chuẩn, còn hỗ trợ các gói tính năng của các nền tảng khác nhau, ví dụ `deb` và `rpm` trên Linux, `msi` và `exe` trên Windows

### JEP 379: Shenandoah (Shenandoah GC, Phiên bản chuẩn)

Bộ thu gom rác Shenandoah được giới thiệu từ Java 12 dưới dạng tính năng thử nghiệm, qua nhiều phiên bản lặp và hoàn thiện, đến Java 15 cuối cùng đã trở thành tính năng chính thức.

Shenandoah là Bộ thu gom rác độ trễ thấp do Red Hat chủ đạo phát triển, mục tiêu chính là:

- 99.9% thời gian tạm dừng GC nhỏ hơn 10ms
- Thời gian tạm dừng không liên quan đến kích thước heap
- Hỗ trợ bộ nhớ heap từ vài trăm MB đến vài TB

Khác với G1 và ZGC, Shenandoah áp dụng thuật toán Đánh dấu - Sắp xếp song song (Concurrent Mark-Compact), có thể thực hiện thu gom rác mà không cần dừng các luồng ứng dụng.

Bật Shenandoah GC:
```bash
java -XX:+UseShenandoahGC className
```

### JEP 339: EdDSA (Thuật toán chữ ký số)

Mới bổ sung thêm thuật toán chữ ký số dựa trên Edwards-Curve Digital Signature Algorithm (EdDSA) có độ an toàn và hiệu năng mạnh hơn.

Mặc dù hiệu năng của nó vượt trội hơn các triển khai ECDSA hiện có, tuy nhiên, nó không thay thế hoàn toàn thuật toán chữ ký số đường cong elip (ECDSA) hiện có trong JDK.

```java
KeyPairGenerator kpg = KeyPairGenerator.getInstance("Ed25519");
KeyPair kp = kpg.generateKeyPair();

byte[] msg = "test_string".getBytes(StandardCharsets.UTF_8);

Signature sig = Signature.getInstance("Ed25519");
sig.initSign(kp.getPrivate());
sig.update(msg);
byte[] s = sig.sign();

String encodedString = Base64.getEncoder().encodeToString(s);
System.out.println(encodedString);
```

Kết quả:

```plain
0Hc0lxxASZNvS52WsvnncJOH/mlFhnA8Tc6D/k5DtAX5BSsNVjtPF4R4+yMWXVjrvB2mxVXmChIbki6goFBgAg==
```

### JEP 378: Text Blocks (Khối văn bản, Phiên bản chuẩn)

Trong Java 15, Text Blocks cuối cùng đã chuyển thành tính năng chính thức, không cần tham số `--enable-preview` nữa là có thể sử dụng.

Text Blocks cung cấp một cách đơn giản hơn để định nghĩa chuỗi nhiều dòng, đặc biệt phù hợp dùng cho các kịch bản như SQL, JSON, HTML.

### JEP 371: Hidden Classes (Class ẩn)

Class ẩn được thiết kế cho các framework, hỗ trợ các class được sinh ra động, những class này không thể bị bytecode của các class khác trực tiếp sử dụng, chỉ có thể sử dụng gián tiếp thông qua Reflection lúc runtime.

Các đặc điểm chính:

- Không thể bị phát hiện: Class ẩn không thể bị phụ thuộc trực tiếp bởi các class khác
- Vòng đời ngắn: Thường sẽ bị unload sau khi dùng xong
- Tối ưu hóa hiệu năng: Cung cấp hỗ trợ hiệu năng tốt hơn cho runtime ngôn ngữ động

Kịch bản áp dụng:

- Runtime ngôn ngữ động (như JavaScript, Groovy)
- Framework sinh bytecode (như ASM, CGLIB)
- Proxy phản chiếu (như Dynamic Proxy)

### JEP 360: Sealed Classes (Sealed class, Xem trước)

**Sealed Classes (Class niêm phong)** là một tính năng xem trước mới trong Java 15.

Trước khi có Sealed Class, trong Java nếu muốn một class không thể bị kế thừa và sửa đổi, chúng ta có thể sử dụng từ khóa `final` để bổ sung cho class. Tuy nhiên, cách này không linh hoạt lắm, chặn đứng luôn kênh kế thừa và sửa đổi của class.

Sealed class có thể hạn chế các class kế thừa hoặc triển khai chúng, nhờ đó class này chỉ có thể được kế thừa bởi các class được chỉ định.

```java
// Abstract class Person chỉ cho phép Employee và Manager kế thừa.
public abstract sealed class Person
    permits Employee, Manager {

    //...
}
```

Ngoài ra, bất kỳ class nào mở rộng sealed class đều bắt buộc phải khai báo là `sealed`, `non-sealed` hoặc `final`.

```java
public final class Employee extends Person {
}

public non-sealed class Manager extends Person {
}
```

![](https://oss.javaguide.cn/javaguide/image-20210820153955587.png)

Nếu class con được phép mở rộng và class niêm phong nằm trong cùng một file mã nguồn, class niêm phong có thể không cần câu lệnh `permits`, trình biên dịch Java sẽ truy xuất file nguồn, bổ sung các class con được cấp phép cho class niêm phong ở thời điểm biên dịch.

### JEP 375: Pattern Matching for instanceof (Khớp mẫu cho instanceof, Xem trước lần 2)

Java 15 tiếp tục đưa khớp mẫu instanceof làm tính năng xem trước, không có điều chỉnh lớn nào, chủ yếu là để thu thập thêm phản hồi sử dụng.

Khớp mẫu instanceof cho phép ràng buộc biến đồng thời khi kiểm tra kiểu, tránh việc chuyển đổi kiểu cưỡng chế thủ công, làm cho mã nguồn gọn gàng và an toàn hơn.

Ví dụ:

```java
// Cách viết truyền thống
if (obj instanceof String) {
    String str = (String) obj;
    System.out.println(str.length());
}

// Cách viết khớp mẫu
if (obj instanceof String str) {
    System.out.println(str.length());
}
```

### Tăng cường API

#### Tăng cường CharSequence

Trước Java 15, nếu bạn muốn kiểm tra một `StringBuilder`, `StringBuffer` hoặc `CharBuffer` có rỗng hay không, thông thường cần gọi `length() == 0`.

Interface `CharSequence` bổ sung một phương thức mặc định `isEmpty()` để kiểm tra chuỗi ký tự có rỗng hay không, nếu có thì trả về true.

```java
public interface CharSequence {
  default boolean isEmpty() {
      return this.length() == 0;
  }
}
```

Do `String`, `StringBuilder`,... đều triển khai interface này, nên hiện tại bạn có thể viết logic kiểm tra theo cách thống nhất và mang tính ngữ nghĩa hơn. Điều này rất thân thiện đối với việc viết mã Generics (xử lý các loại chuỗi ký tự khác nhau).

**Lưu ý:** Mặc dù lớp `String` đã có phương thức `isEmpty()` từ lâu, nhưng đó là do bản thân `String` tự định nghĩa; bước đi này ở Java 15 là đưa khả năng đó "nâng lên" tầng interface.

#### Nâng cao hiệu năng TreeMap

Đây là một tối ưu hóa rất chuyên sâu. Mặc dù các phương thức như `putIfAbsent()`, `compute()` đã xuất hiện trong interface `Map` từ Java 8, nhưng trước Java 15, `TreeMap` chưa tự mình triển khai chúng, mà dùng trực tiếp triển khai `default` trong interface.

**Thay đổi trong Java 15**: `TreeMap` đã chuyên biệt ghi đè các phương thức dưới đây:

- `putIfAbsent()`
- `computeIfAbsent()`
- `computeIfPresent()`
- `compute()`
- `merge()`

**Tại sao phải ghi đè?**

- **Nâng cao hiệu năng**: Triển khai mặc định trong interface thường tương đối "vụng về", thường cần thực hiện tìm kiếm nhiều lần (ví dụ tìm kiếm xem có tồn tại hay không trước, rồi mới quyết định có chèn hay không).
- **Đảm bảo O(log n)**: Triển khai được tối ưu của `TreeMap` có thể gộp việc tìm kiếm và chèn vào trong một lần duyệt cây đỏ đen (Red-Black Tree), tránh việc tìm kiếm cây trùng lặp, nâng cao đáng kể hiệu suất thực thi khi xử lý dữ liệu quy mô lớn.
