## Java 22

JDK 22 được phát hành vào ngày 19 tháng 3 năm 2024, đây là một phiên bản không phải LTS.

Bài viết này sẽ chọn lọc một số tính năng mới tương đối quan trọng để giới thiệu chi tiết:

- [JEP 454: Foreign Function & Memory API (Hàm ngoại và Memory API, Chính thức)](https://openjdk.org/jeps/454)
- [JEP 456: Unnamed Variables & Patterns (Mẫu và biến không đặt tên, Chính thức)](https://openjdk.org/jeps/456)
- [JEP 458: Launch Multi-File Source-Code Programs (Khởi chạy chương trình mã nguồn đa file)](https://openjdk.org/jeps/458)
- [JEP 423: Region Pinning for G1 (G1 Region Pinning)](https://openjdk.org/jeps/423)
- [JEP 447: Statements before super(...) (Flexible Constructor Bodies, Xem trước lần 1)](https://openjdk.org/jeps/447)
- [JEP 457: Class-File API (Class-File API, Xem trước lần 1)](https://openjdk.org/jeps/457)
- [JEP 461: Stream Gatherers (Stream Gatherers, Xem trước lần 1)](https://openjdk.org/jeps/461)

Hình dưới đây thống kê số lượng tính năng mới và thời gian cập nhật mang lại bởi từng phiên bản từ JDK 8 đến JDK 25:

### JEP 454: Foreign Function & Memory API (Hàm ngoại và Memory API, Phiên bản chuẩn)

Sau nhiều vòng ươm tạo và xem trước từ Java 17 đến Java 21, Foreign Function & Memory API (FFM API) cuối cùng đã trở thành tính năng chính thức trong Java 22.

FFM API cho phép các chương trình Java tương tác hiệu quả và an toàn với mã nguồn và dữ liệu bên ngoài Java runtime (như các thư viện C/C++), thay thế cho JNI vốn phức tạp và dễ vỡ.

### JEP 456: Unnamed Variables & Patterns (Mẫu và biến không đặt tên, Phiên bản chuẩn)

Tính năng này cho phép sử dụng dấu gạch dưới `_` để biểu thị các biến không sử dụng hoặc các component không cần thiết trong khớp mẫu, nâng cao tính sạch sẽ và dễ đọc của mã nguồn. Trong Java 22, tính năng này đã chuyển thành phiên bản chính thức.

```java
try (var _ = ScopedContext.acquire()) {
    // Không dùng đến tài nguyên được acquire
}
```

### JEP 458: Launch Multi-File Source-Code Programs (Khởi chạy chương trình mã nguồn đa file)

Java 11 đã giới thiệu khả năng chạy trực tiếp file mã nguồn Java đơn lẻ (`java HelloWorld.java`). Java 22 mở rộng khả năng này cho phép trình thông dịch Java tự động biên dịch và thực thi các chương trình gồm nhiều file mã nguồn Java mà không cần đóng gói thành jar hay biên dịch thủ công trước.

### JEP 423: Region Pinning for G1

Giảm độ trễ cho bộ thu gom rác G1 khi làm việc với JNI (Java Native Interface). Bằng cách ghim (pin) các khu vực bộ nhớ (region) cụ thể chứa các đối tượng JNI thay vì vô hiệu hóa hoàn toàn GC, G1 có thể tiếp tục thu gom rác ở các khu vực khác, giảm đáng kể thời gian tạm dừng ứng dụng.

## Java 23

JDK 23 được phát hành vào ngày 17 tháng 9 năm 2024, đây là một phiên bản không phải LTS.

Bài viết này sẽ chọn lọc một số tính năng mới tương đối quan trọng để giới thiệu chi tiết:

- [JEP 467: Markdown Documentation Comments (Bình luận tài liệu Markdown)](https://openjdk.org/jeps/467)
- [JEP 474: ZGC: Generational Mode by Default (ZGC: Mặc định bật chế độ phân đại)](https://openjdk.org/jeps/474)
- [JEP 471: Deprecate the Memory-Access Methods in sun.misc.Unsafe for Removal (Đánh dấu loại bỏ các phương thức truy cập bộ nhớ trong sun.misc.Unsafe)](https://openjdk.org/jeps/471)
- [JEP 455: Primitive Types in Patterns, instanceof, and switch (Khớp mẫu hỗ trợ kiểu nguyên thủy, Xem trước lần 1)](https://openjdk.org/jeps/455)
- [JEP 466: Class-File API (Class-File API, Xem trước lần 2)](https://openjdk.org/jeps/466)
- [JEP 473: Stream Gatherers (Stream Gatherers, Xem trước lần 2)](https://openjdk.org/jeps/473)

### JEP 467: Markdown Documentation Comments (Bình luận tài liệu Markdown)

Java 23 cho phép viết Javadoc bằng cú pháp Markdown thay vì sự kết hợp giữa HTML và các thẻ Javadoc truyền thống. Điều này giúp tài liệu mã nguồn dễ đọc hơn nhiều ngay cả dưới dạng văn bản thô.

Viết Javadoc bằng Markdown sử dụng ký hiệu `///` ở đầu mỗi dòng:

```java
/// Đây là một phương thức tính tổng.
///
/// * `a` tham số thứ nhất
/// * `b` tham số thứ hai
///
/// Trả về tổng của `a` và `b`.
public int add(int a, int b) {
    return a + b;
}
```

### JEP 474: ZGC: Generational Mode by Default (ZGC: Mặc định bật chế độ phân đại)

Chế độ phân đại (Generational ZGC) được giới thiệu trong JDK 21 hiện đã trở thành chế độ mặc định khi bật ZGC (`-XX:+UseZGC`). ZGC phân đại cải thiện đáng kể thông lượng và giảm mức tiêu thụ CPU bằng cách thu hồi thường xuyên hơn các đối tượng trẻ.

### JEP 471: Deprecate the Memory-Access Methods in sun.misc.Unsafe for Removal

Đánh dấu loại bỏ các phương thức truy cập bộ nhớ trong `sun.misc.Unsafe` để chuẩn bị xóa hoàn toàn trong các phiên bản tương lai. Các nhà phát triển được khuyến khích chuyển sang sử dụng VarHandle (JDK 9) và Foreign Function & Memory API (JDK 22).

### JEP 455: Primitive Types in Patterns, instanceof, and switch (Xem trước lần 1)

Cho phép các kiểu dữ liệu nguyên thủy (`int`, `byte`, `double`,...) được sử dụng trực tiếp trong khớp mẫu `instanceof` và biểu thức `switch`, loại bỏ sự cần thiết phải đóng gói đối tượng.
